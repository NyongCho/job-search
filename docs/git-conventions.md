# 브랜치·커밋·PR 작성 규칙

## 브랜치

영어로 `영역/작업` 형태로 짓고, 여러 단어는 하이픈으로 연결합니다. 예를 들어 사이드바 안내 블록을 제거하는 브랜치는 `ui/remove-sidebar-note`입니다.

## 커밋

한 커밋에는 독립적으로 되돌릴 수 있는 변경 하나를 담습니다. 안내 블록과 그 블록 전용 CSS는 함께 제거하므로 한 커밋에 담습니다.

제목은 `type: 영어 명령형 요약`으로 씁니다. 범위를 적으면 대상이 더 명확해질 때만 `type(scope): 요약`을 씁니다. [Conventional Commits 한국어 명세](https://www.conventionalcommits.org/ko/v1.0.0/)

| 유형 | 용도 | 제목 예시 |
| --- | --- | --- |
| `feat` | 기능 추가 | `feat(dashboard): add a closing-date filter` |
| `fix` | 버그 수정 | `fix: keep the sidebar footer at the bottom` |
| `docs` | 문서 변경 | `docs: document the pull request workflow` |

테스트 추가에는 `test:`, 동작을 유지하는 코드 구조 변경에는 `refactor:`, CI 워크플로 변경에는 `ci:`처럼 변경 목적에 맞는 유형을 씁니다.

## PR

한 PR에는 함께 검토할 주제 하나를 담습니다. 제목과 본문은 한국어로 작성합니다. 제목은 `대상 + 구체적인 변경`이 드러나는 한 줄로 씁니다. 예를 들어 **대시보드 사이드바 하단 안내 블록 제거**라고 쓰면 PR 목록에서도 변경 범위를 알 수 있습니다.

본문은 다음 두 항목을 기본으로 합니다.

- **배경과 변경**에는 변경이 필요한 이유와 달라지는 점을 적습니다. 구현 결정은 이유를 알면 검토에 도움이 되는 경우에 설명합니다.
- **확인 결과**에는 실제로 확인한 조건과 결과를 적습니다. 자동 테스트를 실행했다면 명령과 결과를 함께 기록합니다.

레이아웃 변경은 차이가 드러나는 화면 크기를 적고, 같은 조건에서 찍은 전후 이미지를 나란히 첨부합니다. [당근 SEED Design의 화면 비교 사례](https://github.com/daangn/seed-design/pull/2481)

동작 변경은 리뷰어가 따라 할 수 있도록 사용자 행동 순서와 관찰한 결과를 함께 적습니다. [토스 overlay-kit의 닫기·다시 열기 검증 사례](https://github.com/toss/overlay-kit/pull/187)

운영 설정이나 데이터 변경처럼 병합 전에 판단할 사항이 있을 때는 **배포 시 주의사항**을 추가합니다.

### PR 본문 예시

> **배경과 변경**
>
> 사이드바 하단 안내 블록을 제거했습니다. 기존에는 이 블록의 여백이 푸터를 아래로 밀고 있어, 푸터 자체에 자동 여백을 적용했습니다.
>
> **확인 결과**
>
> - Chrome 1440×900에서 안내 블록이 사라지고 푸터가 하단에 유지되는 것을 확인했습니다.
> - Chrome 390×844에서 메뉴 7개가 한 줄로 배치되고 가로로 스크롤되는 것을 확인했습니다.
> - `make test`로 Python 테스트 87개와 JavaScript 테스트 1개가 통과했습니다.
